# 地图移动、重影与点数增长：检查结论和实施方案

项目：`/home/bob/work/TCK-VILO`。数据：官方 `rooster_2020-03-10-10-36-30_0.bag`，约 167.06 秒。

## 1. 哪些地图移动正常

初始化时估计重力方向、单目尺度，以及视觉/雷达坐标对齐，可以使先前估计整体调整。
当前代码确实存在这些操作：`src/depth_filter.cpp` 中的 `lioInitialization()`
调用 `Map::rotateLidar()`，`vioInitialization()` 和视觉/雷达初始化调用
`Map::scaleRotate()`。不能简单要求建图开始后的所有坐标永久不变。

但对同一条墙或方形边界不断生成位移后的多个副本，不是可以接受的地图结果。
后续优化也允许历史地图修正，前提是旧点随其关键帧更新，而不是保留旧版本再叠加新版本。
全局地图应该采用统一坐标和一致的关键帧位姿；探索新空间会增加点数，重复观察同一区域不应无限增加同一位置的显示点。

## 2. 证据与问题分级

### A. 已确认：原显示地图直接拼接所有历史关键帧，没有跨帧融合

`example/ros_bag_output.h::publishMap()` 原先逐个变换历史关键帧的
`ptr_less_surfs_` 并全部加入输出。虽然核心对单帧和部分局部地图做了体素滤波，
ROS 输出没有跨关键帧融合，同一面墙的重复观测会持续增加显示点数。
每次更新还会遍历全部历史关键帧、重新打包整张地图。

本轮已补：输出地图默认 0.2 米全局体素融合；默认至少间隔 1 秒实际运行时间
重建/发布一次地图；结束时强制发布最终结果。原算法的特征提取和配准分辨率不变。
输出 `map_input_points` 和 `map_points` 分别表示融合前后点数。

这是去重和显示开销修复，不是位姿修复。错开的墙落在不同体素中仍会重影。
当前全量重建仍有随关键帧数增长的计算成本，尚未实现增量子图缓存。

### B. 已确认的时间语义不一致：去畸变没有覆盖所有扫描点

`example/test_vilo_bag.cpp` 在 LIO 初始化后把雷达状态对齐到图像时间，
点时间转换为相对上一雷达状态的时间。`src/frame_handler_mono.cpp::addLidarImageImu()`
也把新雷达状态时间设为当前图像时间。

`src/lidar.cpp::undistPoints()` 的 IMU 轨迹以这个上一状态为起点；但对每点插值时
使用 `(t_pt-min_t)/t_c`，其中 `min_t` 是本扫描首点时间，`t_c` 仍以旧状态为起点。
两者基准不一致，并且采用单位旋转到一个累计姿态的插值，而不是相邻时间节点间插值。

实测官方 Bag 第 24–26 秒，按当前“扫描末点之后第一张图像”的配对规则：
19/19 个可比较扫描的首点早于上一图像状态 19.494–23.204 毫秒。
这些点不在仅从上一状态向当前状态正向积分的轨迹覆盖范围内。
证据：`run/verified_images_motion8/deskew_timing_check.log`。
这是 Bag 时间数据结合当前配对逻辑得到的覆盖缺口，不是已测得的地图几何误差。

该问题尚未修改。不能靠把负时间裁成零、丢掉扫描前段，或无依据地添加固定时间偏移修复。
应统一逐点绝对时间，保留覆盖整帧扫描的 IMU/状态历史，并在相邻轨迹节点之间插值。

### C. 高风险：优化关键帧位姿后，旧局部地图的世界坐标没有同步重建

`src/depth_filter.cpp` 在局部地图构造中从 `surf_features_array` 取已经变换到世界坐标的点，
随后 `liLocalMapping()` 优化关键帧，并把当前扫描按新位姿加入网格。
`src/bundle_adjustment.cpp` 的局部优化回写 `Lidar::setLidarPose()` 和 `lid_poses_map_`，
但这条优化路径没有相应地删除/重投影旧关键帧已经加入的网格点。
初始化的整体旋转会处理网格，但不等于每次局部优化都处理了历史网格。

显示端使用最新关键帧位姿重投影，内部配准地图却可能仍包含旧位姿生成的点。
需要记录每次优化前后的关键帧位姿改变量，并比较重建后的局部地图与现有网格；
尚未量化这一不一致对用户所见重影的贡献。

### D. 架构限制：局部里程计不等于有全局回环的 SLAM

README 将项目描述为 Visual-Inertial-Lidar Odometry。
LIO 初始化后 `key_lidars_list_` 的局部优化窗口保留约 8 个关键帧。
当前调用链未发现完整的全局回环检测/位姿图优化模块。
视觉 `relocalizeFrame()` 不能当作全局地图回环纠正。
长时间重复绕行后的累计漂移可能产生不同位置的场地副本。

不能在尚未修复 B、C 时，把所有重影都归因于没有回环；也不能承诺体素融合能消除累计漂移。

### E. 次要开销与验收缺口

历史 `trajectory` 保留完整 `LidarPtr`；输入窗口也预加载图像、点云和 IMU，
而不是已消费即释放。路径每次重建全历史。长 Bag 的内存和重建成本需要继续剖析。
原来的每扫描线 `std::cerr/std::endl` 会大量同步输出；本轮已接入已有
`VILO_DEBUG_OUTPUT` 开关，默认构建不再逐线打印。异常和真实错误检查未移除。

仓库 RViz 的地图 `Decay Time: 0`、队列 1，路径缓冲 1；不是配置要求保留多张历史 ROS 地图消息。
本次并未检查用户另存的其他 RViz 配置。
之前有限位姿、初始化标志、非空地图和 TF 检查，只证明程序链路可运行，不能证明几何建图质量。

短窗口还表现出明显的运行差异：一轮运动窗口轨迹长度 2.749 米、最大相邻步长 0.211 米，
最终时间戳修复后的同窗口为 5.438 米和 0.667 米。两轮之间未修改配准算法或标定，
但输出时序和线程调度不同，因此这不是严格的单变量算法精度对照。
应把后台种子更新、初始化时序和地图快照一致性纳入后续复查，不能仅凭差异断定已证实某个数据竞争。

## 3. 本轮显示链路补齐

- 发布左右 `sensor_msgs/Image`，保留原图像像素、曝光时间、帧名、编码。ROS 自行重编号 `header.seq`。
- RViz 增加两个 `rviz/Image` 面板，左右图像话题可通过 Launch 指定。
- 图像在初始化之前也发布；结束后保留最后一帧。右图按需流式读取，不再预加载第二份整段图像序列。
- 全局地图体素融合、地图发布限频和默认关闭逐线调试打印，均不改变配准或标定参数。

右图仅显示，原算法仍使用左图。官方 Bag 的话题清单没有 `sensor_msgs/CameraInfo`；
当前 YAML 也不是一份完整的左右双目标定。2D `Image` 显示不需要 CameraInfo 或 TF，
因此未伪造右相机 CameraInfo/外参，也未宣称已经支持 RViz 的标定 3D `Camera` 叠加。
原始雷达和 IMU 由离线入口直接消费；未为了显示而额外重播全部高带宽输入。

## 4. 后续实施顺序

1. 固定同一 Bag 的 30、60、120 秒和完整序列，建立几何与性能基线。
   观察固定墙面区域的厚度/双层间距、点面残差与内点率、轨迹增量、同一区域重复访问误差；
   同时记录地图融合前后点数、占用体素数、构图/发布耗时和内存。
   没有可用真值时不宣称 ATE/RPE 已通过。
2. 优先修正 B：统一 `header.stamp + point.t` 的时间定义，建立覆盖整段扫描及状态时间的惯性轨迹。
   采用相邻节点插值，在同一目标时刻去畸变；使用静止、恒定平移、恒定旋转的已知运动测试，
   再对照 Bag 直墙厚度和配准残差。不改初始化阈值来绕过问题。
3. 修正 C：以“关键帧 ID + 雷达坐标系特征点 + 最新位姿”为权威数据。
   优化后从受影响关键帧重建局部地图/更新空间索引，旧版本不能与新版本共存。
   确认初始化重对齐和后续位姿修正同时作用于内部地图、输出地图、轨迹和 TF。
4. 在统一位姿来源后实现增量地图缓存：更新受影响子图，发布全局体素化展示地图；
   轨迹只保留必要状态，已消费输入按实际生命周期释放。避免通过截掉地图来冒充全局建图。
5. 如果 B、C 修正后完整闭合路线仍明显错位，再独立实施有几何验证的回环约束和全局位姿图优化。
   这是算法能力扩展，不应作为未取证前的默认重构。

## 5. 验收标准

- 左右 Image 像素与 Bag 一致，时戳不超前于 `/clock`，RViz 实际建立订阅连接。
- SLAM 原有崩溃/轨迹/地图/TF 回归持续通过。
- 同一区域重复观察时点数随占用空间而不是观测次数无界增长；探索新区域允许地图增长。
- 用同一几何区域的前后对照证明墙面/边界重影改善，而不仅比较总点数。
- 30 秒以上及完整序列验证持续建图、内存和计算开销；初始化坐标调整与后续异常漂移分开统计。
- 本轮没有完成 B、C 的算法修复、全局回环或完整 167 秒几何验收；不得将显示层改动标成重影已解决。
