# TCK-VILO:A Tightly-Coupled and Keyframe-Based Visual-Inertial-Lidar Odometry System for Mobile Robots With Adaptive Sensor Reliability Evaluation

## ROS Noetic v1.0.0

This repository preserves the original `test_vilo` and adds synchronized offline
ROS bag input, SLAM pose/path/TF output, voxel-fused keyframe feature-map output,
and left/right infrared image displays in RViz. The right image is display-only;
the original visual frontend remains monocular. Upstream:
[yj-dlut/TCK-VILO](https://github.com/yj-dlut/TCK-VILO).

### Clone and build

```bash
git clone --branch v1.0.0 https://github.com/fsdfsdgd/TCK.git TCK-VILO
cd TCK-VILO
source /opt/ros/noetic/setup.bash
bash build.sh
source build/devel/setup.bash
```

C++ changes require recompilation; this is a source release, not a portable
precompiled application. `build/devel/setup.bash` is generated by this build;
there is no root-level `devel` directory in this layout.

Required environment: Ubuntu 20.04, ROS Noetic, GCC 9/C++17, CMake, Eigen3,
Boost thread/system, PCL, SuiteSparse, **OpenCV 3**, and Pangolin.
The verified external versions are OpenCV **3.4.20** and Pangolin **0.6**.
FAST, Sophus and g2o sources are included and rebuilt by `build.sh`.
With Ubuntu/ROS package repositories already configured, common dependencies are:

```bash
sudo apt-get install build-essential cmake libboost-all-dev libeigen3-dev \
  libpcl-dev libsuitesparse-dev ros-noetic-roscpp ros-noetic-rosbag \
  ros-noetic-sensor-msgs ros-noetic-geometry-msgs ros-noetic-nav-msgs \
  ros-noetic-rosgraph-msgs ros-noetic-tf2-ros ros-noetic-tf2-msgs \
  ros-noetic-rviz ros-noetic-tf ros-noetic-rospy
```

Install OpenCV 3.4.20 and Pangolin 0.6 separately using their upstream build
instructions ([OpenCV](https://github.com/opencv/opencv/tree/3.4.20),
[Pangolin](https://github.com/stevenlovegrove/Pangolin/tree/v0.6)). Noetic's
system OpenCV 4 is not a replacement for this release's OpenCV 3 requirement.
For non-default installations, pass their actual CMake configuration directories:

```bash
bash build.sh -DOpenCV_DIR=/your/opencv3/cmake-directory \
  -DPangolin_DIR=/your/pangolin/cmake-directory
```

The build respects these options. It also recognizes the original workstation's
OpenCV location as an optional search hint. Do not add `-march=native` when
linking the system PCL: the project and g2o preserve Eigen's 16-byte ABI.
The build defaults to one job to limit peak compilation memory. If enough RAM
is available, `VILO_BUILD_JOBS=2 bash build.sh` enables two concurrent jobs.

### Launch with the official bag

Bag files are not included in Git. Supply your own local Newer College bag:

```bash
roslaunch vilo test_vilo_bag.launch \
  bag:=/absolute/path/rooster_2020-03-10-10-36-30_0.bag \
  duration:=30
```

Calibration defaults to this checkout's `example/newer_college.yaml`. Override
it with `calib:=/absolute/path/calibration.yaml` when appropriate. The launch
reads the bag directly, publishes `/clock`, and opens RViz; do not also run
`rosbag play`. The first 8 seconds of the official bag are nearly stationary
and may not initialize the visual frontend. A short motion window is
`offset:=19 duration:=8`. Use `rviz:=false` for headless processing.

SLAM output: `/vilo/map_cloud`, `/vilo/path`, `/vilo/pose`, `/vilo/odom`,
`/vilo/lidar_pose`, `/tf`, `/tf_static`. Image output uses the configured
left/right image topics. The map is fused SLAM keyframe surface features,
not the raw LiDAR input or a dense reconstruction.

### Version status and safe development

v1.0.0 is a recoverable working baseline, **not a completed long-sequence
acceptance**. Short motion-window tests have exercised initialization,
trajectory/map output, original image data and TF. A full-bag run has not been
accepted. Long windows can exhaust memory: input sequences and historical
states are retained, and map reconstruction still traverses historical
keyframes. Global display voxel fusion reduces displayed duplicates, not this
entire memory footprint. Deskew time coverage and optimized-map consistency
remain review items. No complete global loop-closure backend is claimed.

Keep v1.0.0 fixed and start subsequent work on a branch:

```bash
git switch -c work/memory-lifecycle v1.0.0
# Edit and test; stage specific source files, not datasets/build products.
git add path/to/changed/source.cpp
git commit -m "Describe the verified change"
git push -u origin work/memory-lifecycle
```

Pushing requires your GitHub write authentication. If using an existing SSH
key, configure the push URL once (HTTPS cloning remains available):

```bash
git remote set-url --push origin git@github.com:fsdfsdgd/TCK.git
```

To recover a clean baseline without overwriting later work, clone the tag into
a new directory and rebuild. To update `main`, review/test the development
branch first and merge normally; never move the published v1.0.0 tag.

See [ROS build/run and verification](docs/BAG_ROS.md) and
[mapping diagnosis and remaining work](docs/MAPPING_REVIEW.md).
The historical machine-specific paths in these reports describe the original
tests; use this README for portable clone/build commands.

## Original standalone interface

## 1. Required Dependencies

### boost
c++ Librairies (thread and system are needed). Install with
	
		sudo apt-get install libboost-all-dev

### Eigen3
Linear algebra.

		sudo apt-get install libeigen3-dev

### OpenCV3
Dowload and install instructions can be found at: http://opencv.org.


### Pangolin
Used for 3D visualization & the GUI.
Dowload and install instructions can be found at: https://github.com/stevenlovegrove/Pangolin.

## 2. Build and Compile

		chmod +x build.sh
		./build.sh

This will create the executable `test_vilo` in *bin* folder.

## 3. Run code

		cd bin
                ./test_vilo \
                lidars=PATH_TO_LIDAR_FOLDER \
                images=PATH_TO_IMAGE_FOLDER \
                imus=PATH_TO_IMU_FOLDER/imu.txt \
                calib=PATH_TO_CALIBRATION_FILE/newer_college.yaml


- `lidars=XXX` where XXX is the folder containing lidar data(both .txt and .bin are ok).
- `images=XXX` where XXX is the folder containing images.
- `imus=XXX` where XXX is the files of imu data (see the *imu.txt* file in *example* folder).
- `calib=XXX` where XXX is a calibration file (see the *newer_college.yaml* file in *example* folder).
